# V-1-14: Contiguous Memory Allocation, багийн ажлын заавар

Энэ файлыг **эхнээс нь төгсгөл хүртэл** нэг удаа уншаад, дараа нь өөрийн даалгаврын хэсгээс эхэлнэ үү.
Ойлгохгүй зүйл байвал гацахгүй, багийн групп дээр асууна (хамгийн доод хэсгийн "Гацвал" хэсгийг үз).

---

## 1. Бид юу бүтээж байгаа вэ

Үйлдлийн систем программуудад **санах ой хуваарилдаг**. Бид энэ ажлыг тооцоолж **загварчилдаг программ** бүтээнэ.
Жинхэнэ санах ойтой ажиллахгүй, зөвхөн тоогоор бодож харуулна.

**Жишээ.** 1000 нэгж санах ой байна гэе. Хэрэглэгч дараах командуудыг өгнө:

```
allocator> RQ P1 200 F      (P1 процесст 200 нэгж өг, First-fit аргаар)
allocator> RQ P2 300 F      (P2 процесст 300 нэгж өг)
allocator> RL P1            (P1-ийн санах ойг чөлөөл)
allocator> STAT             (одоогийн байдлыг харуул)
```

Программ дотроо ийм жагсаалт барина:

```
[0-199 хоосон] [200-499 P2] [500-999 хоосон]
```

Хоосон зай хоёр хэсэгтэй болсон. Үүнийг **fragmentation** (хуваагдал) гэнэ. Хэрэв 600 нэгж хүсвэл нийт хоосон зай
700 байгаа ч нэг хэсэг нь 600 хүрэхгүй тул олгож чадахгүй. Тэгэхэд `C` (compaction) команд P2-ийг эхэнд нь шахаж,
хоосон зайг нэг том хэсэг болгоно.

**Гурван стратеги** (хоосон хэсэг буюу "hole" сонгох арга):

| Тэмдэг | Нэр | Дүрэм |
|---|---|---|
| F | First-fit | Хангалттай том **анхны** hole-ыг ав |
| B | Best-fit | Хангалттай хэмжээтэй **хамгийн жижиг** hole-ыг ав |
| W | Worst-fit | **Хамгийн том** hole-ыг ав |

**Командууд:**

| Команд | Үүрэг |
|---|---|
| `RQ <нэр> <хэмжээ> <F/B/W>` | Санах ой хүсэх |
| `RL <нэр>` | Санах ой чөлөөлөх (зэргэлдээ hole-ууд нэгдэнэ) |
| `C` | Compaction: процессуудыг шахаж hole-уудыг нэг болгоно |
| `STAT` | Хаана юу байгааг харуулах |
| `X` | Гарах |

**Нэгж:** санах ойн хэмжээ ба хаягийг **byte**-аар хэмжинэ (номд `1048576` byte = 1 MB). CLI болон GUI-д нэгжийг "byte" гэж тодорхой бичнэ.

Бидэнд **хоёр интерфейс** байна, хоёулаа нэг **allocator**-ийг ашиглана:
1. **CLI**: текстээр командын мөрөнд ажиллана (`allocator>`).
2. **GUI**: цонх, товчлуур, санах ойг өнгөт тэгш өнцөгтөөр зурсан зураг (багшийн шаардсан "Memory layout").

   ```

   git config --global user.name "Таны Нэр"

   ```

1. **Эхлэхээсээ өмнө хамгийн сүүлийн кодыг татна:**
   ```
   git checkout main
   git pull
   ```

   ```
   git push -u origin feature/cli
   ```

- Нууц үг, хувийн мэдээлэл commit хийхгүй.
- Өөр хүнээс эсвэл AI-аас (ChatGPT, Claude гэх мэт) тусламж авсан эсвэл бэлэн код хуулсан бол **README болон тайланд тэмдэглэх ёстой**. Ахлагчид хэлнэ үү, юу ашигласнаа нуухгүй.

## 4. Allocator-ийг хэрхэн ашиглах вэ (бүгдэд хэрэгтэй)

`src/allocator.py` файлыг нээж уншина (бүх мөр дээр монгол тайлбартай). Дараахыг мэдэхэд хангалттай:

```python
from allocator import Allocator

a = Allocator(1000)                  # 1000 нэгж санах ой үүсгэнэ

ok, message = a.request("P1", 200, "F")   # хүсэх. ok нь True/False, message нь тайлбар
ok, message = a.release("P1")             # чөлөөлөх
ok, message = a.compact()                 # compaction
a.reset()                                 # эхний байдалд оруулах (a.reset(2000) бол шинэ хэмжээтэй)

blocks = a.get_blocks()              # блокуудын жагсаалт
for block in blocks:
    block.start          # эхлэх хаяг
    block.size           # хэмжээ
    block.end()          # сүүлийн хаяг (оролцуулсан)
    block.owner          # процессын нэр. Хоосон hole бол None
    block.is_hole()      # hole мөн эсэх (True/False)

stats = a.get_stats()                # dictionary:
stats["total"]                       # нийт санах ой
stats["used"]                        # ашигласан
stats["free"]                        # чөлөөт
stats["hole_count"]                  # hole-ын тоо
stats["largest_hole"]                # хамгийн том hole
stats["process_count"]               # процессын тоо
stats["external_fragmentation"]      # гадаад fragmentation, хувиар
```

**Анхаарах:** `request`, `release`, `compact` гурвын аль нь ч алдаа гарахад **шалтгаан нь message-д байгаа**, `ok=False` буцаана.
Программ унахгүй. Тиймээс таны ажил бол `ok` ба `message`-ийг хэрэглэгчид харуулах.

Хаяг **оролцуулсан** (inclusive) хэлбэртэй: 200 byte-тай блок 0-оос эхэлбэл `[0:199]` гэж харуулна.

Процессын нэрэнд **зай байж болохгүй** (`P 1` буруу, `P1` зөв). CLI команд зайгаар хуваагддаг тул CLI ба GUI-д ижил дүрэм байхын тулд allocator ийм нэрийг татгалзаж `ok=False` буцаана.

## 6. Даалгавар 2: GUI-ийн зураг (Гишүүн 3)

**Файл:** `src/gui_canvas.py`
**Branch:** `feature/gui-canvas`

### Зорилго
Санах ойг **тэгш өнцөгт мөр** хэлбэрээр зурах. Багшийн шаардсан "Memory layout" дүрслэл. Энэ нь чимэглэл биш, бодит allocator-ийн байдлыг харуулах ёстой.

Одоо `draw_memory(canvas, blocks, max_size)` функц **хамгийн энгийн хэлбэрээрээ ажилладаг**. Таны ажил бол үүнийг сайжруулж бүрэн болгох. **Функцийн нэр, аргументыг өөрчлөхгүй** (Гишүүн 4 үүнийг дууддаг).

### Алхмууд (файл дотор TODO гэж бичсэн)
1. Блок бүрийн **эхлэх хаягийг** тэгш өнцөгтийн доор бичих.
2. **Legend (тайлбар)** нэмэх: `draw_legend` функц бичиж өнгө бүр юуг илтгэхийг харуулах (процесс бүр, hole).
3. Нарийхан блокт нэр багтахгүй бол юу хийхийг шийдэх (жижиг үсэг, эсвэл зөвхөн хаяг).
4. Өөр өөр процесст **өөр өнгө** өгөх (одоо `color_for` зарим үед ижил өнгө өгч магадгүй).
5. **Fragmentation-ийг харагдуулах**: тусдаа hole-уудыг ялгаатай зурах эсвэл гарчигт hole-ын тоо бичих.
6. Зургийн гарчигт нийт хэмжээг нэгжтэй нь (**byte**) бичих. Жишээ: `Нийт: 1000 byte`.

### Хэрхэн туршиж үзэх вэ
GUI бэлэн болтол (Гишүүн 4) өөрийн жижиг туршилтын файл бичиж болно (файлыг commit хийхгүй, зөвхөн өөртөө):

```python
# try_canvas.py  (src фолдерт, commit хийхгүй)
import tkinter as tk
from allocator import Allocator
from gui_canvas import draw_memory

a = Allocator(1000)
a.request("P1", 200, "F"); a.request("P2", 300, "F"); a.request("P3", 100, "F")
a.release("P2")

root = tk.Tk()
canvas = tk.Canvas(root, width=800, height=150, bg="white")
canvas.pack()
draw_memory(canvas, a.get_blocks(), a.max_size)
root.mainloop()
```
Ажиллуулах: `python src/try_canvas.py`

## 7. Даалгавар 3: GUI-ийн цонх, товчлуур (Гишүүн 4)

**Файл:** `src/gui.py`
**Branch:** `feature/gui-window`

### Зорилго
Хэрэглэгчийн ажиллагаатай интерфейс: оролт бөглөж, товч дарахад allocator ажиллаад зураг шинэчлэгдэх.

Одоо цонх нээгдэнэ, санах ойн хэмжээг оруулж "Эхлүүлэх / Reset" дарахад зураг гарна. Үүнийг бүрэн болгоно.

### Алхмууд (файл дотор TODO гэж бичсэн)
1. **Хүсэлтийн мөр:** процессын нэр, хэмжээ оруулах талбар, стратеги сонгох (F, B, W), "RQ" товч. Шошго, статистикт нэгжийг **byte** гэж тодорхой бичнэ (жишээ нь "Санах ойн хэмжээ (byte):", "Хэмжээ (byte):").
2. **Чөлөөлөх мөр:** процессын нэр, "RL" товч.
3. **"C (Compaction)" товч.**
4. **Статистик:** нийт, ашигласан, чөлөөт, hole-ын тоо, хамгийн том hole, fragmentation %.
5. `on_request`, `on_release`, `on_compact` функцүүдийг бичнэ. Бүгд ижил хэлбэртэй:
   ```
   1. allocator эхэлсэн эсэхийг шалгана (self.allocator is None бол алдаа)
   2. оролтыг уншина, хэмжээг int() болгоно (ValueError барина)
   3. ok, message = self.allocator.request(...)
   4. self.message_var.set(message)
   5. self.refresh()
   ```
6. `ok` нь False бол алдааг улаанаар эсвэл `messagebox.showerror`-оор харуулах.

### Шалгах арга
`python src/gui.py` ажиллуулж:
1. Хэмжээ 1000, Эхлүүлэх
2. P1 200 F, P2 300 F, P3 100 F хүсэх
3. P2 чөлөөлөх, зураг дээр hole үүссэнийг харах
4. P4 250 B хүсэх, ямар hole-д орсныг харах
5. Compaction, hole-ууд нэг болохыг харах
6. Алдаа шалгах: хоосон нэр, нэрэнд зай ("P 1"), хэмжээ "abc", хэмжээ 0, олон том хүсэлт, байхгүй процессыг чөлөөлөх

### Зорилго
Программ **зөв ажилладгийг нотлох**. Багш "номын жишээ болон өөрсдийн нэмэлт туршилтаар зөв ажиллагааг нотлох" гэж шаарддаг.
Мөн Peer Review хийх өөр баг таны бэлдсэн жишээ өгөгдлөөр манай программыг шалгана.

Энэ даалгавар **код бичих мэдлэг бараг шаардахгүй**, харин **анхааралтай шалгах, тооцоолох** ажил юм.
Дараах дарааллаар, хялбараас нь эхлэн хийнэ. **A ба B алхам хийсэн бол даалгаварын гол хэсэг гүйцэтгэгдсэн.**

### Хоёр хавтас юунд зориулагдсан вэ

| | `examples/` | `tests/` |
|---|---|---|
| Юу вэ | Командууд бичсэн энгийн **текст файл** | Автоматаар шалгадаг **Python файл** |
| Хэн ажиллуулах | Хүн, CLI-д тэжээж үр дүнг нь хардаг | Компьютер, нэг командаар бүгдийг шалгана |
| Хэрэгтэй газар | Manual, шүүмжлэгч баг | Тайлан ("N тест давсан") |

### A алхам: `examples/` дотор өгөгдлийн файл бэлдэх (хамгийн хялбар, эндээс эхэл)

`examples/example1.txt` бэлэн байгаа. Түүнийг ингэж ажиллуулна (CLI бэлэн болсны дараа):

```
python src/cli.py 1000 < examples/example1.txt
```

Хүлээгдэх `STAT`-ын гаралтууд (файлд 4 удаа `STAT` бий, дарааллаар нь):

```
STAT 1:
Addresses [0:199] Process P1
Addresses [200:499] Process P2
Addresses [500:599] Process P3
Addresses [600:999] Unused

STAT 2 (P1, P3 чөлөөлсний дараа):
Addresses [0:199] Unused
Addresses [200:499] Process P2
Addresses [500:999] Unused

STAT 3 (RQ P4 250 B-ийн дараа):
Addresses [0:199] Unused
Addresses [200:499] Process P2
Addresses [500:749] Process P4
Addresses [750:999] Unused

STAT 4 (Compaction-ийн дараа):
Addresses [0:299] Process P2
Addresses [300:549] Process P4
Addresses [550:999] Unused
```

Дараа нь **өөрөө дор хаяж 3 шинэ файл** бич. Файл бүрийн эхний мөрөнд `#` биш, харин **тусдаа `.md` тэмдэглэл**
(эсвэл `examples/README.md` дотор) хийж "ямар командтай, юу гарах ёстой" гэж бичнэ:

1. `example2_fits.txt`: First, Best, Worst-fit гурав өөр hole-д орох жишээ.
   Санаа: 1000 нэгж санах ой дээр процессуудыг үүсгэж, зарим нь чөлөөлж 3 өөр хэмжээтэй hole гаргаад, дараа нь `RQ` гурвыг F, B, W-ээр өгнө.
2. `example3_compaction.txt`: Fragmentation үүсч, `RQ` бүтэлгүйтэж, `C` хийсний дараа амжилттай болох жишээ.
3. `example4_errors.txt`: Алдааны тохиолдлууд: хэмжээ 0, хэмжээ "abc", буруу стратеги `Z`, байхгүй процессыг `RL`,
   давхар нэр, санах ойноос том хүсэлт, үл мэдэгдэх команд.

Хүлээгдэх үр дүнг **гараар бодож** (цаас, харандаагаар) бичнэ. Дараа нь CLI-ээр ажиллуулж харьцуулна. Зөрвөл тэмдэглэнэ (E алхмыг үз).

### B алхам: `tests/test_allocator.py` дотор бэлэн тестээс хуулж өөрчилж нэмэх

Бэлэн тестүүд (`def test_...`) байгаа. Тэдгээрийн нэгийг **хуулаад, тоонуудыг өөрчилж** шинэ тест болгоно.
Жишээ нь `test_first_fit`-ийг хуулж:

```python
    def test_first_fit_exact_size(self):
        """Яг hole-той тэнцүү хэмжээтэй хүсэлт"""
        a = make_allocator()
        ok, msg = a.request("X", 200, "F")     # анхны hole яг 200 хэмжээтэй
        self.assertTrue(ok)
        self.assertEqual(start_of(a, "X"), 0)
```

Дор хаяж **8 шинэ тест** нэм. Багшийн шаардсан "номын жишээгээр зөв ажиллагааг нотлох" нь **заавал** (доорх эхний хоёр зүйл). Санаанууд:
- **ЗААВАЛ (номын жишээ 1):** 550, 375, 1900, 4500 KB-ийн дөрвөн hole compaction хийвэл нэг 7325 KB hole болно. `test_allocator.py` дотор `test_book_compaction_example` бэлэн бий. Эхлээд уншиж ойлго (4 hole-ыг хэрхэн үүсгэснийг: процесс бүрийг хүсээд, hole болгох процессуудыг чөлөөлсөн). Дараа нь хуулж өөр тоогоор нэг ижил төрлийн тест нэм.
- **ЗААВАЛ (номын жишээ 2):** Номын STAT-ын формат. Энэ нь `test_cli.py` дотор: `RQ P1 200 F`, дараа нь `STAT` хийхэд гаралтад `Addresses [0:199] Process P1` ба `Addresses [200:999] Unused` мөрүүд байх (`Allocator(1000)`-тэй). CLI дууссаны дараа бичнэ.
- Процессын нэрэнд зай орвол татгалзах (`test_name_with_space_rejected` бэлэн бий, үүнтэй төстэй өөр нэг тест бич)
- Яг тэнцүү хэмжээтэй хүсэлт (дээрх жишээ)
- Бүх санах ойг нэг хүсэлтээр авах (`Allocator(100)`, `RQ A 100 F`), дараа нь өөр хүсэлт нэмэхэд амжилтгүй болох
- Best-fit ба Worst-fit өөр hole сонгох (бэлэн `test_best_fit`, `test_worst_fit`-ийг хуулж тоог өөрчил)
- Release хийхэд зүүн талын hole-той нэгдэх, баруун талын hole-той нэгдэх (`len(a.get_blocks())`-ийг шалгана)
- Compaction хийсний дараа `get_stats()["hole_count"]` нь 1 болох
- `Allocator(0)` үед алдаа гарах: `with self.assertRaises(ValueError): Allocator(0)`
- `reset()` дуудсаны дараа бүх санах ой дахин хоосон байх

Ажиллуулах (repository-ийн үндсэн фолдероос):
- Windows: `python -m unittest discover tests`
- Linux: `python3 -m unittest discover tests`

Тест унавал алдааны мессеж "AssertionError: ... != ..." гэж хүлээсэн болон бодит утгыг харуулна. Эхлээд **таны тоо буруу эсэхийг** шалга.
Таны тооцоо зөв, тест унасан бол allocator-т алдаа олдсон гэсэн үг. Тэр үед E алхам руу яв.

## 9. AI ашиглах тухай

AI (Claude, ChatGPT гэх мэт) ашиглаж болно. Дараахыг анхаарна:

1. AI-д **TASKS.md, өөрийн файл, `src/allocator.py`** гурвыг хамт өг. AI кодыг өөрөө харж чадахгүй,
   өгөөгүй бол функцийн нэрийг зохиож бичдэг.
2. AI-д "**зөвхөн <өөрийн файл>-ийг өөрчил, `allocator.py` болон бусад функцийн нэр,
   аргументыг бүү өөрчил**" гэж хэл.
3. Гаргасан кодыг **заавал ажиллуулж шалга** (тест, жишээ). Ажиллахгүй код commit хийхгүй.
4. Кодын ерөнхий үүргийг (юу хийдэг, ямар функц юуг дууддаг) тайлбарлаж чаддаг байх.
5. AI ашигласан бол ямар AI, ямар хэсэгт ашигласнаа **Гишүүн 1-д нэг өгүүлбэрээр хэл**
   (README ба тайланд нэгтгэн тэмдэглэнэ).

Prompt-ийн жишээ:

```
Хавсаргасан TASKS.md, allocator.py, <файл>-ийг уншаарай. Миний ажил: Даалгавар N.
Зөвхөн <файл>-ийг өөрчилнө, allocator.py-д хүрэхгүй, функцийн нэр, аргументыг өөрчлөхгүй.
```
